# PC-G815 Z80 Assembler 仕様

この文書は `packages/assembler-z80` の実装仕様です。

## 1. 目的

- Web UI と CLI で共通の Z80 アセンブラを提供する
- `ORG/ENTRY` で実行開始位置を制御する
- 出力として `BIN + LST + SYM + DUMP` を生成する

## 2. ソース形式

- 1 行 1 文
- コメント: 引用符の外側にある `;` 以降
  - 文字列内の `;` / `,` はデータとして保持する。`\'` / `\"` / `\\` は引用符・バックスラッシュのエスケープ
  - `EX AF,AF' ; comment` の `AF'` と、ラベル名の末尾の `'` は文字列の開始として扱わない
- ラベル:
  - `LABEL:`
  - `LABEL EQU <expr>`
- 大文字/小文字は区別しない（シンボル解決は case-insensitive）

## 3. ディレクティブ

- `ORG <expr>`
  - 現在アドレスを変更する
  - 既定の有効範囲は `0x0000-0x7FFF`（RAM 範囲）。API の `addressRange` で変更できる
  - この行までに解決できるラベル・`EQU` を式で参照できる。後続の未定義シンボルによる配置の先送りはしない
- `ENTRY <expr>`
  - 実行開始アドレス（`0x0000-0xFFFF`）を指定する。出力領域の外側も指定できる
  - 未指定時は先頭 `ORG`、`ORG` もなければ最初の出力アドレスを使用する
  - 後続のシンボルを参照できる。`$` は `ENTRY` 行のアドレス
- `EQU <expr>`
  - 定数シンボルを定義する
  - `$` は定義した行のアドレス。後続のラベル・定数を参照する場合も、この位置を保持する
  - 循環参照・最後まで解決できない参照はエラー
- `DB <item>[, <item>...]`
  - 8-bit データ列
  - 数値式または文字列リテラル
- `DW <expr>[, <expr>...]`
  - 16-bit little endian データ列
- `DS <count>[, <fill>]`
  - 非負の整数 `count` バイトを確保（既定 fill=0）
  - `count` は `ORG` と同様、この行までに解決できる式に限る。`fill` は後続のシンボルも参照できる
- `END`
  - アセンブル終了
- `INCLUDE "path.asm"`
  - CLI では入力ファイル相対で解決
  - Web では includeResolver 未設定のためエラー

## 4. 式

対応演算子（優先順位順）:

1. unary: `+ - ~`
2. `* / %`
3. `+ -`
4. `<< >>`
5. `&`
6. `^`
7. `|`

対応リテラル:

- 10進: `123`
- 16進: `0x7B`, `7BH`
- 2進: `0b1010`, `1010B`
- 8進: `0o77`
- 文字: `'A'`, `'\n'`
- 現在アドレス: `$`

`DB` / `DW` に複数の式を書いた場合、各式の `$` はその文の先頭アドレスを表す。
`DB 'A'+'B'` のような文字定数の演算は、文字列全体とは区別して評価する。
式の最終値が JavaScript の安全な整数範囲を外れる場合はエラー。
数値の `DB` / `DS fill` は `-128..255`、`DW` は下位16ビットを出力する。

### 定数と配置の例

```asm
BASE EQU 0x100
COUNT EQU 3
ORG BASE
START: DS COUNT,0xaa
SIZE EQU $-START
DW SIZE
```

出力は `0100: AAAAAA03 00`、`SIZE` は `3`。
配置計算で各行のアドレス・長さを一度だけ確定し、バイト列生成はその配置を使う。
これにより、定数の解決前後で `ORG` / `DS` の位置とラベルの値が食い違うことを防ぐ。
配置に必要な未定義シンボルは推測せずエラーにする一方、固定長の命令・データでは前方参照を扱う。

### LD のインデックスオペランド

`LD H,(IX+d)` / `LD (IY+d),L` など、インデックス付きメモリと組み合わせる
`H` / `L` は通常のレジスタを表す。
これは [Zilog Z80 CPU User Manual, UM008011-0816](https://www.zilog.com/docs/z80/um0080.pdf)
の「8-Bit Load Group」（印刷ページ71–87）の符号化に従う。

既存の拡張構文 `IXH` / `IXL` / `IYH` / `IYL` は、同じインデックスレジスタの上位・下位、
または `A` / `B` / `C` / `D` / `E` と組み合わせられる。通常の `H` / `L`、メモリ、
別のインデックスレジスタの上位・下位との組み合わせは、指定どおりの命令に符号化できないためエラー。
たとえば `LD IXH,IXL` は有効、`LD IXH,(IX+1)` / `LD (HL),IXH` / `LD H,IXL` は無効。
この上位・下位レジスタ構文は、上記マニュアルに記載された命令とは区別する。

## 5. 出力

- `BIN`: 最初の `ORG` と最小出力アドレスのうち、小さい方を `origin` とする連続バイト列（穴は 0 埋め）
  - 最初の `ORG` より低い位置へ戻って出力しても欠落しない。既定の `entry` は最初の `ORG` のまま
- `LST`: `AAAA: BBBBBBBB CCCCCCCC | source`
- `SYM`: `name = value (kind)`
- `DUMP`: `AAAA: BBBBBBBB CCCCCCCC`

`addressRange` は整数で `0 <= start <= end <= 65535` を満たす必要がある。
`ORG` と各出力区間はこの範囲に収まること。値を16ビットに丸めて範囲内へ戻すことはしない。
複数の `ORG` による区間の重複は、出力する値が同じでもエラー。
割り当てるサイズと区間を検査してから出力配列を作るため、巨大な `DS` を確保してから検査することはない。
全アドレス空間を指定した場合は65536バイトちょうどの出力が可能で、その直後の `EQU` で `$` を使って長さを求められる。

## 6. CLI

```bash
npm run asm -- -i input.asm -o out.bin --lst out.lst --sym out.sym
```

- 既定出力先: `./dist/<input-base>.(bin|lst|sym|dump.txt)`
- `--format dump` で標準出力にダンプを出す
- エラー時は `stderr` に `file:line:column: message` を出力し、終了コード `1`

## 7. Web UI

- タブ: `BASIC` / `ASSEMBLER`（初期 `BASIC`）
- ASSEMBLER タブ:
  - `ASSEMBLE`: ソースをアセンブルしてダンプ表示
  - `RUN`: 直近成功ビルド（または自動アセンブル）を `ORG/ENTRY` で実行
  - `STOP CPU`: 実行停止
  - `NEW`, `Load Sample`: エディタ操作

## 8. エラー方針

- ソースのエラーは例外として呼び出し元へ投げず、`ok: false` と `diagnostics` のファイル名・行・列で報告する
- エラーがある場合、`binary` / `listing` / `dump` / `lst` は空。解決できたシンボルは診断の参考として返す
- `INCLUDE` 内のエラーは展開先ファイルの位置を保持する
- 主なエラー:
  - 未知シンボル
  - 無効オペランド
  - 相対ジャンプ範囲外
  - RAM 範囲外 `ORG` / プログラム配置
  - `INCLUDE` 解決失敗
